#### Phase 1 决策记录（2026-08-20 执行时落盘）

**Proof（product-scope 确认）**：`docs/requirements/product-scope.md` 当前版本（2026-08-20 复核）maintenance 域为第一批扩展域全量在册（`:31` 设备维护——设备、维护计划、维护访问、维护请求、停机记录），全文无任何 OEE 裁剪/降级条目（grep OEE 零命中），延迟范围节（SaaS 多租户/垂直行业）不含 maintenance 能力裁剪。A1.44 §4(iii) 裁决维持成立：OEE 未裁剪 → Q4=(a) 强制实现。结论：**product-scope 无变更，闭环确认**。

**D1（计划运行时间载体）——选择候选 c：窗口内日历班次时长 − 停机时长**
- 裁决：计划运行时间 = Σ `ErpMfgWorkcenterCalendar` 班次窗口时长（与 [dateFrom, dateTo] 相交、isActive、生效期命中、workDatePattern 命中的日期）− Σ `ErpMntDowntimeEntry` 停机时长（该设备与窗口相交的分钟数，开放段计至窗口末端）。L1 UC-MAIN-10 字面「计划生产时长 (排除停机)」的直接实现。
- 班次时长解析：`startTime`/`endTime`（VARCHAR "HH:mm"）可解析 → endTime−startTime（跨午夜 NIGHT 班 +24h）；不可解析时按 shiftType 缺省——ONE_SHIFT=24h、MORNING/AFTERNOON/NIGHT=8h。workDatePattern：null/ALL_WEEK=每日、WEEKDAYS=周一至五、WEEKEND=周六日。
- 替代方案否决理由：a) 纯日历时长含停机时段，违背 L1「排除停机」字面语义；b) JobCard 无计划时长列（plannedQuantity 是数量非时长，工时仅 actualStartTime/actualEndTime 且实仓核验 mfg 业务代码零写入 `setActualEndTime`），无载体。
- 无数据分支：设备无 workcenterId / 工作中心无生效日历行 / 窗口内无命中工作日 → 计划运行时间 null → 可用率 null（D4）。
- 残留风险：①日历 seed 缺省班次时长（8h/24h）是近似口径（无显式时段时）；②跨午夜班按 +24h 展开与次日窗口可能双计（按班次归属起始日计，不做跨日切分）；③停机与日历时段不重叠时扣减可能使计划时长低于实际语义（钳制 ≥0 后交 D4）。

**D2（理论产量口径）——标准产能 × 实际运行时间；产能行按「窗口产品优先→唯一行回退→否则 null」**
- 裁决：理论产量 = `ErpMfgWorkcenterCapacity.capacityPerHour`（每小时产能）× 实际运行时间（= 可用率分子，StatusLog Σ RUNNING 窗口段——owner doc §6.2「理论产量 = 标准产能 × 运行时间」之「运行时间」与可用率分子同源，标准 OEE 语义）。产能行选择（实仓核验 materialId 为 mandatory，无通用行）：①窗口内经报工记录归属该工作中心的工单产品集（TimeLog→WorkOrder.productId）恰一个产品 → 取该 workcenter+product 的 active 产能行；②否则该 workcenter 恰一条 active 产能行 → 取该行；③否则 null。
- `efficiencyFactor` 不参与乘积（L1/owner doc 字面公式仅「标准产能 × 运行时间」；效率系数属排产负荷维度）。单位不换算（capacityPerHour 单位/小时 × 小时，自然对齐）。
- 无数据分支：设备无 workcenterId / 无 active 产能行 / 多产品混合且无唯一产能行 / 实际运行时间 0 → 理论产量 0 或 null → 性能效率 null（D4）。
- 残留风险：多产品混合窗口理论产量不可计算（保守 null，不虚计）；产能行 per-material 语义下 fleet 级横向对比受产品结构影响。
- 实际产量载体补充裁决（数据源映射）：实际产量 = Σ `ErpMfgJobCardTimeLog.completedQuantity`（workDate ∈ 窗口，经 JobCard.workcenterId 桥接）——TimeLog 为 owner doc §6.2「工单报工记录」的逐班报工实体（workDate/completedQuantity/scrappedQuantity，`ErpMfgJobCardRecordWorkProcessor` 报工写入链）；JobCard.completedQuantity 头级累计无窗口时间载体（actualEndTime 业务侧零写入，实仓核验）故仅作桥接。

**D3（质量分子口径）——主数据源 a（qa Inspection）+ 缺数据回退 b（mfg 报工数量）**
- 裁决：主路径——合格品数 = Σ `ErpQaInspection.lotQuantity`（result=ACCEPTED 且 relatedBillType=`ERP_MFG_WORK_ORDER` 且 relatedBillCode ∈ 窗口内该工作中心报工归属的工单 code 集 且 inspectionDate ∈ 窗口）；质量合格率 = 合格品数 / 总产量（总产量 = D2 实际产量，L1「合格品 / 总产量」字面）。CONDITIONAL（让步接收）不计合格（dict 字面「合格」=ACCEPTED）。回退路径——窗口内零关联质检记录时：质量合格率 = Σ TimeLog.completedQuantity / (Σ completedQuantity + Σ scrappedQuantity)（mfg 报工数量路径）；回退分母 0 → null。两路径均分母 0/无产量 → null（D4）。
- 弱指针镜像常量：mnt 侧定义 `RELATED_BILL_TYPE_MFG_WORK_ORDER = "ERP_MFG_WORK_ORDER"`（镜像 `ErpQaConstants`/`ErpMfgConstants` 不可变值，调用方副本先例 `ErpMntConstants.RELATED_BILL_TYPE_MNT_SPARE_PART`）。
- 残留风险：①qa 批量与 mfg 报工数量口径可能不同步（检验滞后/抽检）→ 比率理论可 >1，不钳制（如实呈现，owner doc 字面语义）；②工单跨多工作中心时其质检合格量计入每个报工归属工作中心（按报工归属归因，工程近似）。

**D4（零除与空窗口语义）——null 非 0，不 config 化**
- 裁决：任一分量分母为 0 或数据缺失 → 该分量 null；三分量任一 null → OEE null（不做 0 乘）。窗口默认值镜像 getDashboardKpi（dateFrom=本月 1 日、dateTo=今天）。「无数据 ≠ 零效率」——卡片/列表显示层呈现 "—"。**不新增 config**（口径为公式语义非运营策略；若后续运营要求兜底口径再立项，Non-Goals 已排除）。
- 与 owner doc §6.1 公式对齐校验：可用率=实际运行时间/计划运行时间 ✅；性能效率=实际产量/理论产量 ✅；质量合格率=合格品/总产量 ✅；OEE=三者乘积 ✅；数据来源 §6.2 五行全覆盖（实际运行时间=设备状态记录 ✅ 计划运行时间=生产计划[日历−停机，L1「排除停机」] ✅ 实际产量=工单报工记录[TimeLog] ✅ 理论产量=标准产能×运行时间 ✅ 合格产品数=质检记录 ✅）。无冲突，无需反向改契约。

## Current Baseline

- **A4.2.163（SP-1 UC-B2B-001 isActive=false 格式运行时是否仍被 Registry 派发；P2-RC-062）**：静态判定 = `ErpB2bEdiDocCreateOutboundProcessor#findFormatByCode:91-97` 查 `ErpB2bEdiFormat` 仅判 null 不查 isActive → inactive 格式仍参与派发。运行时确认 inactive 格式经 createOutbound 是否仍被选中。
- **A4.2.164（SP-2 UC-B2B-002 needsWebService=true Provider 是否经隐式机制走异步队列；reuse P1-MA2-073）**：静态判定 = `ErpB2bEdiDocCreateOutboundProcessor#createOutbound:39-71` 同步直发，`needsWebService` 分支零调用（`UblInvoiceEdiProvider#needsWebService:93` return false）。运行时确认异步队列/发送 Job 存在性（grep scheduler/cron/queue census）。
- **A4.2.165（SP-3 UC-B2B-003 入站 webhook EdiDoc 是否经隐式 hook 自动 archive；P2-RC-064）**：静态判定 = `ErpB2bAsnHandleInboundWebhookProcessor#parseToAsn:87-171` 零 archive 调用 → EdiDoc 留 RECEIVED。运行时确认 archive 触发机制（`ErpB2bEdiDocBizModel.archive():160-161` 守卫仅允许 RECEIVED→ARCHIVED 合法迁移，其余态抛 illegalTransition；`TestErpB2bEdiPosting#testArchiveAfterAcknowledged:106-123` 证实 ACKNOWLEDGED→archive 抛 NopException 状态不变）。
- **A4.2.166（SP-4 UC-B2B-004 出站 UBL Invoice 物料编码是否经 codeMappingResolver 映射；P2-RC-065）**：静态判定 = `UblInvoiceEdiProvider` 注入 `codeMappingResolver:35` 但 `#generatePayload:51-84` 未调用 resolveOutbound（入站 parseToAsn:156 调 resolveInbound 已证实）。运行时确认出站报文物料编码实际为内部原值。
- **A4.2.167（SP-5 UC-B2B-006 ERROR+WARN blocking_level 是否存在隐式自动重试调度；reuse P1-MA2-073）**：静态判定 = grep autoRetry/@Scheduled/Quartz/cron 跨 module-b2b main 零命中 + markError 恒设 blockingLevel=ERROR 无 WARN 分级 → 无自动重试。运行时确认重试仅手工 `ErpB2bEdiDocBizModel#retry:112-126`。
- **A4.2.168（SP-6 UC-B2B-007 activate 是否可从 TESTING/CERTIFIED 直接跳 PRODUCTION 绕过门槛；P1-RC-080）**：静态判定 = `ErpB2bPartnerProfileBizModel#activate:22-27` 任意态→PRODUCTION 零状态守卫 + 推进 mutation/通过率门槛/认证清单全零实现。运行时确认 activate 绕过门槛实际可达。
- **A4.2.169（SP-7 UC-B2B-008 证书过期是否经 scheduler 自动停用 MftConfig；P2-RC-068）**：静态判定 = `ErpB2bMftCertificateBizModel#findExpiringCertificates:39-50` 仅查询无 scheduler/deactivation。运行时确认停用机制缺失（仅查询能力存在）。

剩余差距：七项均为只读运行时确认。缺陷项（P1-RC-080 维持 P1 Q4 强制实现；范围内 P2 项 062/064/065/068 登记不强制）修复归 MR1；本计划仅确认运行时行为以维持/细化裁决，不实施修复。

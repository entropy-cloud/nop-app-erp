# 评估 Checklist（v3.3）

> **真相源**：`00-methodology.md`（本文档应**引用**而非复述）
> **Roadmap**：`docs/backlog/optimization-audit-roadmap.md`（v3）
> **状态**：M0.3 done
> **本文档是"子 agent 产出是否达标"的验证标准**
> **重要提醒**：本 checklist 是**验证标准**，不是评估的全部。子 agent 应在此基础上发挥**独特洞察**，发现 checklist 未覆盖的别扭模式与改进机会。

---

## ⚠️ 重要：checklist 是验证标准，不是评估天花板

> **给子 agent 的提醒**：
>
> 本 checklist 定义了评估文档的**最低验证标准**。
>
> 但**真正有价值的发现往往超出 checklist**：
>
> - 本 checklist 的 12 类别扭模式是**通用模板**——子 agent 应发现本域特有的额外模式
> - 本 checklist 的检查项是**示例**——子 agent 应根据本域特点调整/扩展
> - 满足所有 checklist 项 ≠ 优秀评估；真正优秀 = checklist 全过 + 独特洞察
>
> **执行者验证**：未达 checklist 项 = 不合格；达到 checklist 项 = 合格；达到 + 独特洞察 = 优秀。

---

## 1. 文件级 Checklist（每个评估文件必查）

> **详见** `00-methodology.md §5 调研深度门槛`

## 10. 给子 agent 的最后提醒

> **本 checklist 是验证标准，不是天花板**。
>
> 真正有价值的评估来自子 agent 的**独特洞察**——那些不在 checklist 中、但确实存在于代码中的别扭模式。
>
> **鼓励**：
> - 质疑 checklist 的标准
> - 发现 checklist 未覆盖的别扭模式
> - 提出比 checklist 建议更深入的改进方案
> - 跨子 agent 关联发现
>
> **底线**：checklist 全过 + 独特洞察 = 合格的深度评估。

# Paperless-ngx 调研报告

> **文档管理系统**（GPL-3.0）：OCR 全文搜索 + 自动分类打标 + 邮件摄取 + AI 模块，把物理文档转化为可搜索的在线归档。对 nop-app-erp 的参考价值：**文档驱动的 AP/应收自动化**（发票/票据 → OCR → 分类 → 入账的前端管道）与 **消费管道（consumption pipeline）** 架构。

## 1. 基本信息

| 项 | 值 |
|---|---|
| 技术栈 | Python/Django 5 后端 · Angular 前端（src-ui/）· PostgreSQL + Redis（Celery/channels） |
| License | GPL-3.0 |
| 定位 | 文档管理——keep less paper，物理文档转可搜索在线归档 |

## 2. 核心架构（源码实测）

- `src/{documents,paperless,paperless_mail,paperless_ai}`：
  - **documents**——归档/消费管道核心：OCR（含远程 OCR parser）、自动分类（机器学习打标：标签/对应方/单据类型）、全文搜索、REST API
  - **paperless_mail**——**邮件摄取**：邮箱轮询→附件入管道→自动归档
  - **paperless_ai**——AI 模块（LLM 辅助分类/元数据）
  - django-auditlog 审计日志

## 3. 对 nop-app-erp 的借鉴

| # | 借鉴点 | Paperless-ngx 证据 | 对 nop 的落地建议 |
|---|--------|-------------|-------------------|
| 1 | **消费管道模式（ingest→OCR→classify→archive）** | documents 管道 + 队列 | 发票/应收票据自动化的前端参考：扫描件→结构化单据→过账的管道化设计 |
| 2 | **自动分类（ML + 规则）** | 自动打标/对应方识别 | 与 nop 的 AP 三单匹配（订单/入库/发票）衔接的智能预处理 |
| 3 | **邮件摄取** | paperless_mail | 供应商发票邮件/EDI 之外的补充入口（对照 b2b 域 MFT/EDI） |
| 4 | **全文搜索与审计** | 搜索 + auditlog | 单据附件的可检索归档与 nop-file 模块对照 |

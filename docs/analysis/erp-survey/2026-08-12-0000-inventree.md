# InvenTree 调研报告

> 开源**库存管理系统**（MIT）：底部库存控制 + 部件追踪 + 制造（build/工单）+ 采购销售，配套**强大插件系统**与**机器学习集成**。对 nop-app-erp 的 inventory/manufacturing 域是"小而美"的实现参考，其 **report 报告生成** 与 **machine 机器学习** 插件模式值得对照。

## 1. 基本信息

| 项 | 值 |
|---|---|
| 技术栈 | Python/Django + DRF 后端 · React 前端（Mantine + TanStack Query）· PG/MySQL/MariaDB/SQLite + Redis |
| License | MIT |
| 定位 | 开源库存管理——powerful low-level stock control and part tracking |

## 2. 业务域（源码实测 `src/backend/InvenTree/`）

| 域 | 内容 |
|----|------|
| part | 部件/分类/参数/替代件（multi-level） |
| stock | 库存项/位置/批次/序列/调拨 |
| build | 制造工单/BOM（Build + BomItem） |
| order | 采购/销售/退货单（PurchaseOrder/SalesOrder） |
| company | 供应商/制造商/客户 |
| report | **报告生成**（标签/表单模板，WeasyPrint） |
| machine | **机器学习集成**（模型注册/推理） |
| plugin / plugins | **插件系统**（registry + 钩子） |
| importer / data_exporter | 数据导入导出 |

## 3. 对 nop-app-erp 的借鉴

| # | 借鉴点 | InvenTree 证据 | 对 nop 的落地建议 |
|---|--------|-------------|-------------------|
| 1 | **插件注册模型** | plugin registry + 生命周期 | 与 NocoBase 插件生命周期、Fleetbase 扩展索引三方对照，评估 nop 的 Delta + SPI 自定义边界 |
| 2 | **报告模板化生成** | report/（标签/表单） | 对照 nop-report 的打印/标签场景（序列号标签、出入库单） |
| 3 | **机器学习集成模式** | machine/ 模型注册 + 推理 | 预测（需求/补货）在 ERP 内的落点参考——对应 frePPLe mlforecast 的另一形态 |
| 4 | **部件参数体系** | part 参数/替代件 | 主数据设计的轻量参考（对照 ErpMdMaterial + 参数扩展） |

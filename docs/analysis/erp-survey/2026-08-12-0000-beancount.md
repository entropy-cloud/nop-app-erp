# Beancount 调研报告

> **纯文本复式记账 DSL**（GPL-2.0）：用文本文件定义金融交易、严格平衡校验、生成报表、Web 界面。与 Ledger 同源。对 nop-app-erp finance 域的参考价值在**记账内核的严格性与可审计性**——"GL 不可变 + 强制借贷平衡 + 全文即账本"是记账内核的极端简洁范例。

## 1. 基本信息

| 项 | 值 |
|---|---|
| 技术栈 | 纯 Python（无数据库——文本文件输入、内存加载） |
| License | GPL-2.0 |
| 定位 | Double-Entry Accounting from Text Files（复式记账计算机语言） |

## 2. 核心架构（源码实测）

- `beancount/{core,ops,parser,plugins,scripts,tools,projects,utils}`：
  - **parser**——严格校验：语法、借贷平衡、期初/期末一致性
  - **ops**——操作层（交易规范化）
  - **core**——数据模型 + **查询引擎**（类 SQL）
  - **plugins**——插件系统（自动转账识别、汇率补全等）
  - **scripts**——报表/导入导出（web UI、beancount-language-server 等）
- 记账模型：账户树（Assets/Liabilities/Income/Expenses/Equity）+ 复式分录 + postings 平衡约束

## 3. 对 nop-app-erp 的借鉴

| # | 借鉴点 | Beancount 证据 | 对 nop 的落地建议 |
|---|--------|-------------|-------------------|
| 1 | **强制借贷平衡的 parser** | 平衡校验贯穿 parser/ops | nop 凭证引擎的借贷平衡校验可对照其约束清单（借=贷、账户必须存在于科目树、金额非零） |
| 2 | **GL 不可变 + 冲销语义** | 文本即不可变账本（更正=新交易） | 与 nop 红字冲销设计理念一致；印证"冲销而非修改"是行业正解 |
| 3 | **账户树显式定义** | 科目树 + 每交易引用账户 | 对照 nop 的科目体系（ErpMdSubject）与凭证模板 |
| 4 | **查询引擎** | core 的类 SQL 查询 | 账本可编程查询的参考（对照 nop 的 EQL/BizQuery） |

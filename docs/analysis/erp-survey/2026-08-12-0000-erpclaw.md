# ERPClaw 调研报告

> 声称是**首个开源 AI-native ERP**（GPL-3.0，v4.14.0，46 模块 / 3,234 actions / 789 表）。核心创新不在 AI 模型本身，而在**架构**：AI 助手为主交互界面、动作层即 API、GL 不可变（冲销=反向分录）。对 nop-app-erp 最有参考价值的是其"action 层 + 不可变记账内核"设计，与 Nop 的 BizModel/凭证引擎对照阅读。

## 2. 核心架构（源码实测）

### 2.1 动作层即 API

- 所有操作统一入口 `scripts/db_query.py --action {action} --args`，14 个核心域 + meta/os 基础设施：
  `erpclaw-{setup,gl,selling,buying,inventory,billing,tax,payments,journals,reports,hr,payroll,accounting-adv,os,meta}`
- 每个 action 是单个事务，失败整体回滚；GL 条目不可变（更正=反向分录），无 `updated_at` 列
- 金额存 TEXT(Decimal)、ID 用 UUID4、money 精度全程受控

### 2.2 模块注册表与按需安装

- `scripts/module_registry.json` 登记全部模块，从 `github.com/avansaber/*` 按需 sparse checkout（45+ 可选行业模块）
- 网络访问仅限汇率 API 与模块安装（需用户确认）——本地优先安全模型

### 2.3 MCP 服务

- 内建 `mcp/server.py` 与 `mcp/tool_router.py`，以 MCP 协议暴露 action——AI 通过标准协议读写业务数据

### 2.4 治理

- 状态变更 action 需要 per-invocation 用户确认标记（AI 无法绕过）
- 不可变审计日志记录每个 action 的完整输入输出与 GL 分录
- ed25519 签名模块注册表，严格模式拒绝未签名/篡改模块

## 3. 对 nop-app-erp 的借鉴

| # | 借鉴点 | ERPClaw 证据 | 对 nop 的落地建议 |
|---|--------|-------------|-------------------|
| 1 | **动作层即 API 的统一入口** | `db_query.py --action` 统一路由 | 与 Nop 的 BizModel/GraphQL 自动暴露对照；如引入 AI 助手，所有 BizMutation 已是 action 化基础 |
| 2 | **不可变 GL + 反向冲销** | GL 条目不可变，无 updated_at | nop 已有红字冲销设计（`posting.md`）；对照其"审计日志不可变"的 schema 级约束 |
| 3 | **模块按需安装（registry）** | module_registry.json + sparse checkout | 对应 nop 的 Maven 模块制与 `module-meta.json` 管线（BT5 风格依赖声明，见 strategic-gaps 3.12） |
| 4 | **MCP 暴露业务能力** | mcp/tool_router.py | 调研参考仅此（**平台裁决 2026-08-12：应用与 Nop 平台均不采用 MCP，API 由 GraphQL 类型定义描述、REST/GraphQL 双通道调用，见 `docs/design/ai-native-interface.md` §1**） |
| 5 | **AI 安全护栏** | per-invocation 确认 + 签名注册表 + 审计 | nop 的 enforcement 栈（action-auth/SoD）已覆盖权限；可对照 AI 场景的确认流设计 |

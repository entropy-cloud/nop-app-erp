# Fleetbase 调研报告

> **模块化物流与供应链操作系统**（AGPL-3.0）：Laravel 后端 API + Ember.js 控制台 + **可安装扩展机制**。自带 ledger 记账包、IAM 引擎、AI 包、遥测集成——团队将其从物流平台扩展为"供应链 + 记账"操作系统的架构路径对 nop-app-erp 的 **logistics 域** 与 **模块化扩展设计** 有参考价值。

## 1. 基本信息

| 项 | 值 |
|---|---|
| 技术栈 | PHP/Laravel 10（api/）· Ember.js（console/）· Node.js CLI（monorepo packages/） |
| License | AGPL-3.0 |
| 定位 | Modular logistics and supply chain operating system（模块化物流与供应链 OS） |

## 2. 核心架构（源码实测）

### 2.1 扩展机制（Extensions）

- 分包注册 + **extensions indexer**：第三方扩展可安装/升级/停用（`packages/extensions`、`packages/core-api`）
- 动态订单配置：rules / flows / automation（物流订单的规则与自动化引擎）

### 2.2 平台包（packages/）

| 包 | 用途 |
|----|------|
| fleetops | 车队运营（订单/任务/司机/车辆/路线） |
| fleetops-data | 运营数据模型 |
| **ledger** | **记账包**（物流计费/结算的双重记账内核） |
| iam-engine | 动态 IAM 权限系统 |
| storefront / customer-portal | 商户端/客户门户 |
| **ai** | AI 包（LLM 应用） |
| pallet | 遥测/硬件集成 |
| ember-core / ember-ui / registry-bridge | 前端控制台与注册桥 |

### 2.3 API 形态

- RESTful API + WebSocket + Webhooks（`api/app/Models` + 事件）；动态 IAM 控制租户/组织/角色

## 3. 对 nop-app-erp 的借鉴

| # | 借鉴点 | Fleetbase 证据 | 对 nop 的落地建议 |
|---|--------|-------------|-------------------|
| 1 | **平台化扩展机制** | extensions indexer + 分包注册 | 对照 nop 的模块制（Maven + Delta）：Fleetbase 的"可安装扩展"是 NocoBase 插件生命周期之外的另一种形态 |
| 2 | **物流域核心对象** | fleetops（订单/任务/司机/车辆/路线） | 对照 nop logistics 域状态机（承运商网关 SPI + 运输状态机） |
| 3 | **订单规则/自动化引擎** | rules/flows/automation | 复杂物流订单的自动化配置层参考（对比 nop 的规则抽笔设计） |
| 4 | **ledger 与业务域同仓** | packages/ledger | "物流平台自带记账内核"的边界取舍对照：nop 选择 18 域独立 finance 域 + 过账引擎，更彻底 |

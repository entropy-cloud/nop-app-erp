# frePPLe 调研报告

> 开源 **APS（Advanced Planning and Scheduling）** 标杆：C++ 优化求解引擎 + Python/Django 业务层，**约束理论**（围绕瓶颈排产）、拉动式/精益计划、ML 需求预测。直接对口 nop-app-erp 的 **aps 域（工序级排产引擎）** 与 `2026-07-20-post-survey-strategic-gaps.md` 识别的 **MRP/DRP 仿真缺口**。

## 1. 基本信息

| 项 | 值 |
|---|---|
| 技术栈 | Python + Django（djangorestframework + channels websocket）· **C++ 求解引擎**（src/）· Vue 前端 |
| 数据库 | PostgreSQL |
| License | AGPL-3.0 |
| 定位 | 供应链需求预测与高级计划排程（APS），面向制造企业 |

## 2. 核心架构（源码实测）

### 2.1 双层架构

- `src/{model,solver,forecast,utils}`——**C++ 核心**：模型 + 约束求解器 + 预测算法
- `freppledb/`——**Django 业务层**：`common`（通用）、`forecast`（预测）、`input`（输入）、`output`（结果）、`execute`（执行）、`reportmanager`（报表）、`webservice`（API）、`wizard`、`metrics`（KPI）、`archive`（归档）

### 2.2 求解方法

- 约束理论（TOC）：围绕瓶颈资源排产、拉动式（pull）计划、精益制造
- 时间序列需求预测 + **ML 预测模块**（`mlforecast/`，多模型集成）

### 2.3 ERP 对接

- `erpconnection/`（通用连接器）+ `odoo/`（Odoo 适配）——外部 ERP 的物料/订单/库存双向同步，输出计划到 ERP 工单/采购建议

## 3. 对 nop-app-erp 的借鉴

| # | 借鉴点 | frePPLe 证据 | 对 nop 的落地建议 |
|---|--------|-------------|-------------------|
| 1 | **求解引擎与业务层分离** | C++ solver + Django 业务层 | nop 的 aps 域若引入约束求解，可将算法独立于 ORM 业务层 |
| 2 | **瓶颈驱动排产（TOC）** | 约束理论排产 | 对照 nop aps 的有限产能正反向排程，补充瓶颈识别与拉动式视角 |
| 3 | **预测与排产衔接** | forecast + mlforecast → solver 输入 | 需求预测模块与 MRP/APS 的接口设计参考；对 strategic-gaps 3.7"MRP/DRP 仿真引擎"有直接借鉴（场景化预测 → 多方案计划） |

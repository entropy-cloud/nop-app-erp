## 1. 需求契约原文（L1，逐字引用）

### UC-MAIN-01 预防性维护自动调度(时间周期)（use-cases.md:16-30）

**场景**：nop-job 按时间周期(如每月)自动生成维护访问 DRAFT。

**可验证断言**（逐字引用 use-cases.md:21-26）：
```
nop-job 定时任务 →
  按维护计划(周期类型=时间, 频率) → 生成维护访问(DRAFT)
  套用维护任务模板(标准工时/标准备件)
维护访问.设备/计划时间/任务清单 填充
```

**定时作业接线**（use-cases.md:30，逐字引用）：「UC-MAIN-01 的 nop-job 触发已接线：`ErpMntDueVisitJob` + `app-service.beans.xml` `<bean>` + `scheduler.yaml` 条目。cron 门控键 `erp-mnt.due-visit-cron`（默认空=跳过；非空时以 `LocalDate.now()` 为基准调 `IErpMntScheduleBiz.generateDueVisits()`）。」

逐条验收标准拆解（进入 L5 判读）：
- **UC-MAIN-01-A**：nop-job 定时任务接线（cron 门控）
- **UC-MAIN-01-B**：按维护计划(周期类型=时间, 频率) → 生成维护访问(DRAFT)
- **UC-MAIN-01-C**：套用维护任务模板(标准工时/标准备件)
- **UC-MAIN-01-D**：维护访问.设备/计划时间/任务清单 填充

### UC-MAIN-02 运行时长触发维护（use-cases.md:34-45）

**场景**：设备累计运行时长达到阈值(如每 5000 小时),触发维护。

**可验证断言**（逐字引用 use-cases.md:39-43）：
```
周期类型=运行时长
设备累计运行时长 >= 阈值 → 生成维护访问(DRAFT)
运行时长来源: 设备状态记录(RUNNING 时长累计)
```

逐条验收标准拆解（进入 L5 判读）：
- **UC-MAIN-02-A**：周期类型=运行时长（Schedule 需支持运行时长触发类型）
- **UC-MAIN-02-B**：设备累计运行时长 >= 阈值 → 生成维护访问(DRAFT)
- **UC-MAIN-02-C**：运行时长来源 = 设备状态记录(RUNNING 时长累计)

### UC-MAIN-09 排程冲突检测（use-cases.md:151-162）

**场景**：同一设备/人员同时段排程冲突。

**可验证断言**（逐字引用 use-cases.md:156-159）：
```
维护访问 SCHEDULED →
  校验: 设备/人员 同时段是否已有排程
  冲突 → 警告或拒绝(配置决定)
```

逐条验收标准拆解（进入 L5 判读）：
- **UC-MAIN-09-A**：维护访问 SCHEDULED 时校验同时段排程
- **UC-MAIN-09-B**：校验维度 = 设备 **和** 人员（双维度）
- **UC-MAIN-09-C**：冲突 → 警告或拒绝（配置决定 warn/reject）

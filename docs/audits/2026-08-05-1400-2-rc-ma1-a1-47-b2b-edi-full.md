## 1. 需求契约原文（UC-B2B-001~008 验收标准逐字引用）

> 来源：`docs/design/b2b/use-cases.md`（逐字引用，`:line` 写时实测导航）

### UC-B2B-001 EDI 格式配置（`use-cases.md:3-32`）

- 基本流：「新增格式记录 指定格式名称/标准/方向/是否需 WebService」→「保存 → 生成 ErpB2bEdiFormat 记录」。
- 业务规则（逐字）：「每种格式对应一个 `IErpB2bEdiProvider` bean（按 `getCode()` 匹配）」「`isActive=false` 的格式不参与适用性派发」「格式配置是 Provider 的元数据，Provider 实现负责实际的报文生成和解析」。

### UC-B2B-002 EDI 出站发送（`use-cases.md:35-66`）

- 基本流（逐字）：「ErpB2bEdiRegistry 按 relatedBillType 查适用格式 Provider」「生成 ErpB2bEdiDoc(state=TO_SEND)」「Provider.generatePayload() 生成 EDI 报文」「Provider.needsWebService() 判断 true → 入异步发送队列，cron 轮询发送；false → 同步 HTTP POST 发送」「发送成功 → state=SENT」「记录 ErpB2bEdiLog」。
- 备选流（逐字）：「格式不匹配 无适用 Provider → 设 blocking_level=INFO，状态不变」「发送失败 state=ERROR」。
- 业务规则（逐字）：「UNIQUE(formatId,relatedBillType,relatedBillCode) 保证同一格式同一业务单仅一条 EDI 事务」「已存在的 ediDoc（非终态）返回已有记录，不重复创建」。

### UC-B2B-003 ASN 入站接收（`use-cases.md:69-102`）

- 基本流（逐字）：「HMAC 签名验证」「Provider.parsePayload() 解析报文」「建 ErpB2bEdiDoc(state=RECEIVED, relatedBillType=PO_ORDER)」「建 ErpB2bAsn(status=RECEIVED)」「建 ErpB2bAsnLine」「记录 ErpB2bEdiLog」「EdiDoc state → ARCHIVED」。
- 备选流（逐字）：「签名失败 拒绝请求，blocking_level=ERROR」「解析失败 EdiDoc state=ERROR，保留报文到 EdiLog」「无匹配采购订单 ASN 仍创建，relatedBillCode 为空」。
- 业务规则（逐字）：「ASN 不直接写库存（等待 purchase 域决定）」「ASN 可追溯回来源 EDI 报文（sourceEdiDocId）」「无匹配采购订单时 ASN 也可创建」。

### UC-B2B-004 代码映射管理（`use-cases.md:105-129`）

- 业务规则（逐字）：「同一 partnerId + mappingType + internalCode 唯一」「无映射时 出站 EDI 使用内部代码，入站 EDI 使用外部代码原值」「映射在 generatePayload（内部→外部）和 parsePayload（外部→内部）时双向使用」。

### UC-B2B-005 Webhook 集成（`use-cases.md:132-163`）

- 出站场景（逐字）：「EDI 发送器调用 ErpSysWebhookConfig 中配置的端点」「HTTP POST + HMAC 签名」「记录 ErpSysWebhookLog」。
- 入站场景（逐字）：「Trading Partner 推送 EDI 报文到本系统 Webhook 入站端点」「HMAC 验签 → 进入 ASN 接收流程」「记录 ErpSysWebhookLog」。
- 业务规则（逐字）：「Webhook 出站认证方式由 ErpSysWebhookConfig 配置」「本模块的 EDI 入站端点路径约定 `/r/b2b/webhook/inbound/{formatCode}`」「Webhook 日志用于审计和排错」。

### UC-B2B-006 错误处理与重试（`use-cases.md:166-202`）

- 基本流（逐字）：「筛选 state=ERROR」「重试 state→TO_SEND（出站）或 RECEIVED（入站）」「放弃 state→CANCELLED」。
- 自动重试策略（逐字表）：「ERROR 且 blocking_level=WARN → 系统每 30 分钟自动重试，最多 3 次」「ERROR 且 blocking_level=ERROR → 不自动重试，需人工介入」「重试 3 次仍失败 → blocking_level 升级为 ERROR」。
- 业务规则（逐字）：「重试使用新的 EdiDoc state 迁移，不修改原 error 记录（保留审计轨迹）」「原 EdiLog 保留，重试产生新的 EdiLog 记录」。

### UC-B2B-007 合作伙伴上线（`use-cases.md:220-231`）

- 基本流程（逐字）：「REGISTERED：填写伙伴档案」「推进至 TESTING：交换 EDI 报文，**验证通过率≥90%**」「推进至 CERTIFIED：逐项完成认证检查清单，**所有必检项通过**」「推进至 PRODUCTION：切换生产端点与凭证，**设置 goLiveDate**，**上线监控 24 小时***」「终止合作时下线归档（status=TERMINATED，**archivedAt 记录**）」。
- 异常（逐字）：「测试通过率不达标或必检项未通过时无法推进至下一阶段」。

### UC-B2B-008 MFT 配置（`use-cases.md:234-244`）

- 基本流程（逐字）：「配置协议（AS2/SFTP/FTPS）端点+凭证/证书」「管道选项：压缩（GZIP/ZLIB）、加密（PGP/SMIME）、签名（SHA-256）」「重试策略：maxRetries、retryIntervalMin、deadLetterEnabled」「SFTP 协议时可配置监控目录和轮询间隔」「文件传输时系统自动记录 ErpB2bMftLog」「传输失败时按重试策略自动重试；重试耗尽进入 DEAD_LETTER 状态」「证书管理：导入证书，支持有效期监控和自动告警」。
- 异常（逐字）：「证书过期时 MFT 配置自动停用（active=false）」「端点不可达时按重试策略处理」「fileHash 校验失败时标记 FAILED」。

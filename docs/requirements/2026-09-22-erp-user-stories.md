# ERP 平台通用用户故事（联网调研综合）

> Status: draft for review
> Date: 2026-09-22
> Type: 需求侧用户故事综合（非实现就绪 Feature 需求）
> Related: `docs/requirements/product-scope.md`、`docs/design/feature-inventory.md`、`docs/analysis/2026-09-22-erp-user-story-gap-analysis.md`
> Skill: none（无匹配可复用技能；按 `00-requirement-synthesis-guide.md` 骨架裁剪为用户故事体）

## 目的

从公开 ERP 资料（Oracle/NetSuite 模块论、Odoo/ERPNext 角色与 UAT 场景、行业 use case 文集）归纳「一般 ERP 平台应提供什么、谁在什么场景下用」，沉淀为可对照检查本仓库的用户故事集。本文**不替代** `product-scope.md` / 各域 owner doc；是否纳入产品以差距分析裁决为准。

## 调研输入（摘要）

| 来源类型 | 代表材料 | 提炼要点 |
|---------|---------|---------|
| 模块论 | Oracle 10 ERP modules；NetSuite 13 modules / 12 core features / 8 components | 财务为基石；采购、库存、订单、制造、CRM、HR、分析为高频模块；横切能力=集成、自动化、报表、实时可见性 |
| 场景文 | NetSuite 15 use cases；EPROMIS/Eventura 等 | 库存实时可见→补货决策；RFQ→PO；报价→订单→发票；制造纸质→系统；月末关账提速 |
| 角色与 UAT | Odoo UAT playbook；ERPNext roles；CNPERP/Cetec 角色表 | 按部门角色授权；职责分离；本人数据 vs 经理全量；三单匹配；拣配发；审批阈值 |
| 深度能力 | Odoo Purchase/Barcode 文档；2026 趋势文 | 条码扫码收发存盘；移动审批；审计日志；多币种；预算控制 |

## 角色（Personas）

与 `docs/design/roles-and-permissions.md` 业务角色对齐，另补外部/管理视角：

| ID | 角色 | 典型目标 |
|----|------|---------|
| P1 | 采购员 | 快速寻源下单、到货与发票一致、供应商可控 |
| P2 | 销售员 | 报价转订单、客户与价格可视、发货收款闭环 |
| P3 | 库管员 | 收货上架、拣配发货、盘点准确、扫码少录入 |
| P4 | 财务员 | 业财一体过账、往来核销、月末快速关账出表 |
| P5 | 生产计划/主管 | 需求可计划、齐套可开工、报工可结转成本 |
| P6 | 质量/维护人员 | 检验有标准、不合格可追溯、设备按计划维护 |
| P7 | 管理层/总经理 | 实时经营看板、审批不堵车、异常可下钻 |
| P8 | HR/行政 | 员工入转调离、考勤薪酬、费用报销不跑腿 |
| P9 | 系统管理员/IT | 账号角色、审计合规、集成与扩展可控 |
| P10 | 客户/供应商（外部） | 自助查单、确认协同、少邮件电话 |

## 用户故事

编号规则：`US-<域缩写>-<序号>`。验收条件为最小可检验断言（详细业务规则仍归各域 owner doc）。

### Epic A：主数据与组织（Master Data）

| ID | 用户故事 | 验收条件（摘要） | 关联角色 |
|----|---------|------------------|---------|
| US-MD-01 | 作为主数据维护员，我想要统一维护物料/SKU、单位换算与条码，以便各域引用同一商品真相 | 物料 CRUD + 多单位换算 + barcode 唯一 | P9, P3 |
| US-MD-02 | 作为业务员，我想要客户/供应商统一档案（含地址、结算、价格档），以便下单时少填错 | 往来单位 CRUD + 业务引用不重复建档 | P1, P2 |
| US-MD-03 | 作为财务，我想要科目表、币种汇率、组织树按模型配置，以便多组织多币种核算有骨架 | COA/币种/组织实体可配置并被单据引用 | P4, P9 |
| US-MD-04 | 作为管理员，我想要主数据变更可审计、可停用而非硬删，以便追溯历史单据 | 软停用/审计字段；删除受引用约束 | P9 |

### Epic B：采购到付款（P2P）

| ID | 用户故事 | 验收条件（摘要） | 关联角色 |
|----|---------|------------------|---------|
| US-PO-01 | 作为采购员，我想要从询价/比价生成采购订单并跟踪状态，以便按需下单不遗漏 | RFQ→报价→PO 链路；PO 状态可见 | P1 |
| US-PO-02 | 作为采购员，我想要按订单收货（支持部分收货），以便仓库与采购口径一致 | 收货写库存；部分收货数量约束 | P1, P3 |
| US-PO-03 | 作为财务，我想要订单-收货-发票三单匹配，以便只付该付的钱 | 不匹配告警/阻断；匹配结果可查 | P4 |
| US-PO-04 | 作为财务，我想要发票审核后自动生成应付并支持付款核销，以便往来账可审计 | 过账回链；open-item 核销闭环 | P4 |
| US-PO-05 | 作为采购主管，我想要超阈值订单走审批且创建人≠审批人，以便内控合规 | 审批轴 + SoD 拒绝自审 | P1, P7 |
| US-PO-06 | 作为采购员，我想要退货与供应商绩效/评分可见，以便持续改善供应质量 | 退货单；评分卡/评级 | P1 |

### Epic C：销售到收款（O2C）

| ID | 用户故事 | 验收条件（摘要） | 关联角色 |
|----|---------|------------------|---------|
| US-SO-01 | 作为销售员，我想要快速建档报价并转销售订单，以便缩短成交周期 | 报价/商机→SO；状态流转 | P2 |
| US-SO-02 | 作为销售员，我想要客户价格档、信用/折扣规则下单时生效，以便报价一致可追溯 | 价格档/折扣应用可查 | P2 |
| US-SO-03 | 作为库管，我想要按 SO 拣配发货并校验可用库存，以便不超卖不错发 | 可用量校验；出库扣减 | P2, P3 |
| US-SO-04 | 作为财务，我想要发货开票收款核销一体，以便应收清晰 | 发票→收款→核销；账龄可查 | P4 |
| US-SO-05 | 作为客服/销售，我想要退货换货流程与原单回链，以便售后有据 | 退货入库/退款；关联原 SO | P2, P10 |
| US-SO-06 | 作为销售管理，我想要管道预测与配额对比，以便判断目标达成 | 预测/配额/实际同屏口径 | P2, P7 |

| ID | 用户故事 | 验收条件（摘要） | 关联角色 |
|----|---------|------------------|---------|
| US-IV-01 | 作为运营，我想要实时库存余额与流水，以便补货与差异排查 | 余额=流水汇总；实时查询 | P3, P7 |
| US-IV-02 | 作为库管，我想要跨仓调拨与在途可见，以便库存布局合理 | 调拨状态机；在途数量 | P3 |
| US-IV-03 | 作为库管，我想要盘点生成盘盈盘亏并过账，以便账实相符 | 盘点差异→移动单→凭证 | P3, P4 |

| US-IV-06 | 作为计划员，我想要安全库存/补货建议（DRP/MRP 输入），以便避免缺货积压 | 净需求计算；建议单可释放 | P1, P5 |

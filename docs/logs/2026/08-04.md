### 2026-08-04（调研：Velpos vs Mission-Driver 外部 Agent 驱动器对比 — 落盘分析文档）

- **任务**：应提问完成 Velpos（`C:/can/ai/velpos`，Claude Code Web 控制台）与 AGE Mission-Driver（`C:/can/nop/attractor-guided-engineering-template/tools/mission-driver/`）的对比调研，并落盘为分析文档。纯文档，零代码/ORM/CI 变更。
- **核心结论**：两者同为"外部编排器"（驱动黑盒 CLI Agent，均不实现 Agent 引擎），正交形态——
  - Velpos = 交互式 Web 产品（人在环）：流式 chat、权限请求回传（`PermissionRequestBlock.vue`）、Git worktree 分支对比、IM 双同步（飞书/微信/QQ/OpenIM）、Team/AgentSlot/Handoff 团队编排；无状态机，成果判定靠人。
  - mission-driver = 无人值守 Headless 状态机：FlowEngine（CHECK→REVIEW_PLANS→EXEC_PLANS→DRAFT_PLANS→DEEP_AUDIT）、磁盘文件 marker 通信（`<AI_STEP_RESULT>` + markerAliases）、plan 复选框 + closure audit + BUILD_VERIFY 契约判定完成、断点恢复、9 源文件零依赖 stack-agnostic。
  - 本质差异：人在环 vs 无人值守、有无状态机（最大鸿沟）、契约判定 vs 人判定、实时双向 vs 单向事后文本（mission-driver 无法处理运行时需人确认场景）、产品 vs 可移植引擎。
  - 定位一句话：mission-driver 做"自治"，Velpos 做"交互"；可与 nop-ai-agent（自研白盒引擎）并存不同层，本对比不涉及。
- **落盘**：`docs/analysis/2026-08-04-0000-velpos-vs-mission-driver.md`（6 节：快照证据来源/定位图/对比表/五差异/复杂度来源/使用场景判断/结论）+ `docs/analysis/README.md` 顶层索引条目。交叉引用已有方法论文章 `docs/articles/mission-driver--loop-engineering.md`、`docs/articles/beyond-mission-driver-from-loop-control-to-attractor-guided-engineering.md`。

### Flux 集成 Gotcha 入档（G-001：`CrudQueryFormConfig.mode` 不控制 label 位置）

- **发现路径**：本次视觉修复诊断过程意外暴露 nop-chaos-flux 的设计怪味——开发者直觉会设 `<queryForm mode="horizontal">` 控制 label 位置，但实际无效；flux `data-schema-validation.ts:23` 读的是 `queryForm.layout`，**两个 `mode` 字段同名但语义完全不同**（输入 schema 的 `mode` = `'manual'|'auto'` 控制 autoGenerateQueryFilter；渲染 form 的 `mode` = `'normal'|'horizontal'|'inline'` 控制 label 位置）。
- **设计根因（已定位）**：`CrudQueryFormConfig.mode` 类型 `'manual'|'auto'` 用于控制自动生成行为；`CrudQueryFormConfig.layout` 类型 `'horizontal'|'vertical'|'inline'` 用于控制布局方向；但渲染后的 form 的 `mode` 字段（label 位置）是 `data-schema-validation.ts:23` 通过 `queryForm.layout === 'horizontal' ? 'horizontal' : 'normal'` 派生出来的——两个字段同名不同义，docstring 未声明这一约定。
- **是否修改 nop-chaos-flux**：**本次不动**，按 AGENTS.md「跨仓库原则」修改需双独立子 agent 批准 + plan。当前 workaround 已在 `grid_crud.xpl` 落（同时设 `layout + mode`）。
- **改进方向**（不入本轮，作为后续 plan 候选）：
  - 短期：在 `CrudQueryFormConfig.mode` 加 docstring 说明与 layout 的语义差异（微改、零破坏）
  - 中期：让 `data-schema-validation.ts` 同时读 `queryForm.layout` 和 `queryForm.mode`，让 `mode` 在 queryForm 语境下也接受 label 位置字符串（破坏性，需同步改 type 定义）
- **入档**：`docs/architecture/flux-integration-gotchas.md` 新建（G-001 条目含症状/根因/workaround/推荐修复/关联代码/落地状态五段；预留模板供后续 gotcha 追加）。

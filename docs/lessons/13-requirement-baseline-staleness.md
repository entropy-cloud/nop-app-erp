# Lesson 13: 需求基线陈旧——真相源与 owner doc 事实性表述随实现演进漂移未被审计

> **来源**：2026-08 requirement-compliance mission 0.2（基线提取修正）+ RC-R1.89 草案审查 BLOCKER。0.2 清单化时发现 product-scope 计数漂移、use-cases 非标准 heading 与标题重复；RC-R1.89 迭代 1 因 payroll.md「hr 模块零 xbiz」审计快照型过时表述被独立审查判 BLOCKER（基线伪事实致 D2 替代方案分析建立在错误前提）。
> **适用场景**：任何把文档断言当**前提**消费的工作——审计基线提取、fix plan 替代方案分析、owner doc 更新、里程碑回填。引用"X 不存在 / X 计数是 N / 零 X 文件"类事实断言前必查。
> **失败模式**：需求/事实基线（product-scope 计数、use-cases 结构、owner doc 事实性表述）在实现演进后**被动陈旧**，而下游消费者（审计、修复计划、新特性设计）仍按陈旧断言推理——伪事实沿引用链传播，轻则计数漂移误导基线对比，重则 BLOCKER 级错误前提（替代方案分析整体作废）。

## 核心论点

基线陈旧的危害不是"文档不整洁"，而是**伪事实被当前提消费**。两类高发载体：

1. **计数/状态型断言**（product-scope 成功指标、roadmap §当前基线、测试计数）：每次实现里程碑落地后天然漂移，若无"指向权威计数源"的指针设计，每个复制点都是潜在第二真相源。
2. **审计快照型断言**（"零 xbiz 文件"“无 X 实体”“未实现 Y"）：写于某次审计时点，**实现推进后自动失效**，且失效是静默的——没有任何机制提醒引用方重验。快照型断言的有效期 = 审计时点到下一次实仓变化之间，把它当持久事实引用是结构性错误。

防御机制三层：①引用前 grep 实仓重验（快照型断言）；②实现里程碑落地后回扫引用该断言的文档（本计划改了什么，谁曾断言它不存在）；③计数类断言一律指向权威计数源（known-good-baselines / surefire XML 权威计数），不内联复制数值。

## 失败模式（典型路径）

```
1. 审计/设计文档写下事实断言（"模块零 xbiz" / "计数 1902" / "UC 共 189"）
2. 后续实现里程碑落地（M4.64 写入 36 个 xbiz / 测试增长到 1903+ / heading 归一化）
3. 断言所在文档无人回扫 → 静默失效
4. 下游消费者把断言当前提：
   a. 计数对比 → 基线"漂移"假阳性/假阴性
   b. 替代方案分析 → 某选项因"X 不存在"被否决，而 X 实际存在 → 分析整体作废（BLOCKER）
5. 独立审查（或更晚的审计）发现伪事实 → 返工 + 信任损耗
```

## 决策树：引用文档事实断言前

```
1. 断言类型是什么？
   → 计数/状态型：找权威计数源（known-good-baselines / surefire XML / roadmap §当前基线），
     以权威源为准；本文档若内联了数值，标注"写时实测"并接受后续漂移不回改（对齐 methodology 锚点纪律）。
   → 快照型（"零 X" / "无 Y" / "未实现 Z"）：进入步骤 2。
   → 需求契约型（范围/验收标准）：按真相源层级消费（product-scope/use-cases 权威），非本课对象。

2. 快照型断言：grep 实仓重验（一条命令的成本 < 一个 BLOCKER 的返工）。
   → 断言仍真：引用并注明"写时实测"。
   → 断言已失效：先改断言所在文档（或加纠正注记），再做下游推理。

3. 本里程碑是否新增/改变了某物（新文件族 / 新实体 / 新机制）？
   → 是：rg 全 docs/ 找"零/无/未实现 <该物>"类断言，逐处回扫更新（RC-R1.89 Phase 3 范式）。
```

## 自检清单（写文档 / 引用断言 / 里程碑收尾时）

- [ ] 写下的"零 X / 无 Y"断言是否标注了时点（审计快照型）？是否在实现推进后回扫过？
- [ ] 引用他人文档的快照型断言前 grep 实仓重验了？
- [ ] 计数类数字是否优先指向权威计数源而非内联复制（README §验证状态 指针范式）？
- [ ] 里程碑落地新增文件族/实体/机制后，是否 rg 扫过 docs/ 中与之矛盾的旧断言？
- [ ] 独立审查发现伪事实时，是否修的是**断言源头**而非仅修当前计划的引用？

## 何时复发

- 长周期 mission 中期，早期审计报告的快照断言被后期修复计划直接引用。
- 手写 xbiz / delta / job 等文件族批量引入的里程碑（M4.64 型）落地后无人回扫 owner doc。
- 成功指标 / 测试计数被多处内联复制，单点更新其余漂移。

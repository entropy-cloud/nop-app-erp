# Lesson 23: `_cases` 快照对齐必须外科式文本变换——禁 `force-save-output` 全量重录

> **来源**：2026-09 ai-check-r3 mission MI.6 批 1/批 2 + MI.7 + MI.8 批 2（plan `2026-09-07-0902-1` / `2026-09-07-1715-1` / `2026-09-07-0902-2` / `2026-09-07-1715-2`；落盘 plan `2026-09-11-1425-1` MG.1）。证据基 = MI.6 批 1 快照治理实录：约 133 文件外科式文本变换 + `force-save-output` 全量重录实测会窄化通配符断言而弃用。
> **适用场景**：任何改变**持久化消息/名称/摘要类字符串载体**（LOG 文案、audit 内容、MEMO/reason/label/report 标签、错误消息载体、i18n 英文化等）的修复或清剿批——实体业务数据被 `_cases` 快照断言捕获、但 seed CSV 未变更时，快照必须与代码载体同步对齐。
> **失败模式**：用 `force-save-output`（或等价全量重录通道）"顺手"更新快照——把 HEAD `*` 通配符与 `@var:` 掩码展开成本次运行的字面值，断言从「结构不变式」窄化为「本次运行字面快照」；下一次合法数据变化即红，且窄化不可逆地摧毁了原本受保护的断言自由度。

## 核心论点

快照中的 `*` 通配符与 `@var:` 前缀是**断言自由度的承载**——全量重录不是"刷新基线"，是**单方面收窄测试契约**。载体列变更的对齐粒度必须是「列」而非「文件」：只改断言语义确实变化的消息/名称/摘要列，其余逐字节保持。trap 面（全量重录）与正确面（外科变换）在 r3 成对出现：MI.6 批 1 明确实测弃用 `force-save-output`，此后 MI.6 批 2 / MI.7 / MI.8 批 2 全部沿外科协议执行。

## 协议要素（r3 验证有效）

| # | 要素 | 反面（缺此要素时） |
|---|------|-------------------|
| 1 | 旧值→新值仅限消息/名称/摘要列，diff 逐列核验 | 全文件重录混入不可解释漂移 |
| 2 | 保留 `*` 通配符与 `@var:` 前缀（从 HEAD 取回字面保留） | 通配符展开成字面值，断言窄化 |
| 3 | CSV 重写按 RFC 4180：新值含逗号按 QUOTE_MINIMAL 重引号（MI.6 批 1 fulfillment lastError 族实证） | 引号丢失 → 列解析错位伪失败 |
| 4 | seed 字典名列按 seed 真相对齐（FK 映射），不保留旧字面量（MI.6 批 1 SUBJECT_NAME「折旧费用」→ 种子名「管理费用」） | 保留旧字面 → 与 seed 真相漂移 |
| 5 | seed CSV / 通知模板 / fixture 注入行零改动（确须变更触发 seed-data.md §快照重录双面义务走独立程序） | 顺手改 seed → 静默扩大变更面 |
| 6 | 等价重序列化须语义树复验：MI.8 批 2 对 quoted-key labelMap / flow→block / literal-block 变换以 PyYAML parse 剥离 `i18nEn` 后与 HEAD 语义树逐节点一致抽样复验 | 只看文本 diff → 键序/引号风格变化混入语义漂移 |

## 真实案例（r3 四批实录）

- **MI.6 批 1**（plan `2026-09-07-0902-1`）：fin/ast/cs 181 行 CAT-3 清剿触发约 133 文件快照外科变换（旧值→新值仅限消息/名称/摘要列，保留 `*` 通配符；`force-save-output` 全量重录实测窄化通配符断言，弃用）。

- **MI.7**（plan `2026-09-07-0902-2`）：顺带修复 MI.6 批 1 跨模块 `_cases` 快照遗留 38 文件 + 1 测试断言（期望值外科同步，均有 code 实锚验证，非生产行为变更）。
- **MI.8 批 2**（plan `2026-09-07-1715-2`）：17 域 1318 行 `i18nEn` 补齐触发 yaml 等价重序列化，语义树逐节点等价抽样复验（行为不变式未破坏）。
